# Validation status

There are two distinct sets of evidence: the original full-model GPU experiments, and checks of this newly packaged cookbook. The serving recipe uses the exact final measured Python overlays and CUDA implementation; the portable launcher, service installer and documentation are new packaging.

## Original inference work

On four A100-SXM4-40GB GPUs:

- All five speedup hypotheses were measured; rejected results are preserved.
- A matched final 128-token suite measured 4.78 → 107.88 single decode tokens/s.
- The optional custom kernel passed numerical reference tests and a four-suite full-model comparison against a fresh stock control.
- The final candidate passed 3 cache unit tests, 32/32 prefix-reuse checks, and 13/13 functional checks.
- A 190,422-token complete-book prompt passed marker/factual-answer review. Cold/cached answers and stock/tuned answers were byte-identical; two summary inaccuracies are explicitly documented.
- The production deployment passed API health, exact image/arguments/overlay identity, native context and read-only model checks.

These are the archived inference measurements, not results generated by GitHub Actions.

## Cookbook packaging

The following were checked while preparing this repository:

- All numbered patches reconstruct the shipped Python overlays and tuned CUDA header exactly from pinned originals.
- All seven original source files inside the pinned container image match their recorded image hashes; all overlays compile syntactically in its Python runtime.
- The optional extension builds from the cookbook source with the pinned image's Torch/CUDA compiler. No GPU inference was needed for compilation.
- The Project Gutenberg download and bundled compressed fixture recreate the exact raw/clean book hashes.
- Nine launcher/profile tests cover path spaces, pinned image/context/precision, ownership protection, failed-stop behavior, single-manager use, missing binaries, descriptor inheritance and lock release.
- Generated model-serving arguments were compared directly with the live tested production arguments and matched (apart from the configured port).
- A disposable CPU-only container exercises the generated systemd service: start, restart/recreation, recovery after kill, intentional stop, and released process lock. Its Podman create command is translated to a simple sleeping Python process. This validates lifecycle behavior, not full-model startup.
- Repository checks cover Python syntax, overlay hashes, documentation links and known private-path/address patterns.

The full model was not stopped and redeployed through the new portable service during repository preparation. Follow the README's startup and correctness checks on your own deployment. This limitation is deliberate and separate from the already measured runtime recipe.

## Run the checks

Offline/CPU-side checks (Linux, Python 3.10+, Git and flock):

```bash
python3 -m unittest discover -s tests -v
python3 scripts/check_repository.py
```

Pinned upstream reconstruction (network access required):

```bash
python3 scripts/verify_patches.py
```

Container/source and extension build checks:

```bash
python3 scripts/cookbook.py check-image
python3 scripts/cookbook.py build-kernel
```

Optional service lifecycle smoke test, on a host with a functioning systemd user manager and the pinned image already pulled:

```bash
python3 scripts/test_service.py
```

This creates a uniquely named temporary service/container, uses no GPU/model, and removes it afterward. It does not install or alter the normal model service. The script's test fixture intentionally substitutes a CPU process for the large model.

Actual GPU correctness and performance commands are in README.md and the kernel/experiment guides. The GitHub workflow runs CPU-side unit/repository checks and pinned patch reconstruction only; it does not have A100s.

## Packaging issues found and fixed

- The historical standalone PLE patch was incomplete relative to the final overlay. The cookbook regenerates the patch from the pinned source, then checks byte-for-byte reconstruction.
- The first service smoke test exposed a mixed-Podman-path failure: an interactive shell used a newer Podman while the user manager could resolve the system copy. The unit now pins the exact Podman executable for both start and stop using QWEN_COOKBOOK_PODMAN. The first test failed restart readiness; it is not counted as a pass.
- The disposable CPU test process initially ignored SIGTERM as container PID 1, making stop tests wait for the timeout. The fixture now explicitly handles SIGTERM. This was a test-fixture change, not a model-runtime optimization.
